# Integrity EV Solutions Website

Website for Integrity EV Solutions, a licensed electrical and EV charging contractor in Georgia.

Live site: https://www.integrityevsolutions.com

This is a plain HTML website. There is no framework, no build step and nothing to install. What you see in this repo is what gets published.

## What is in here

```
index.html                     Home page
services/<name>/index.html     The six service pages
privacy-policy/, terms-of-service/, sitemap/, thank-you/   One folder each, with an index.html inside
404.html                       Page shown for addresses that do not exist
index/index.html               Small page that sends /index to the home page
styles.css                     The site's styling
site.js                        The site's behavior (menus, FAQ, contact form, phone number)
images/                        Logo, service photos and work-gallery photos
cody-lander.jpg, integrity-logo.png, favicon.svg, site.webmanifest   Owner photo, logo and icons
robots.txt, sitemap.xml        For search engines
CNAME                          Tells GitHub Pages the custom domain. Do not delete.
.nojekyll                      Tells GitHub Pages to publish the files as they are. Do not delete.
```

A page's address matches its folder. For example, `services/tesla-powerwall/index.html` is `https://www.integrityevsolutions.com/services/tesla-powerwall/`.

## Publishing

1. In the repo, go to **Settings > Pages**.
2. Under **Source**, choose **Deploy from a branch**. Set the branch to `main` and the folder to `/ (root)`.
3. Under **Custom domain**, enter `www.integrityevsolutions.com` and turn on **Enforce HTTPS**.
4. DNS for `www` must point to GitHub Pages (`<account>.github.io`).

After that, every change saved to the `main` branch is published automatically within a minute or two.

## Editing

**Text, links and headings:** open the page's `index.html`, search for the words, change them and save.

**The menu and footer are repeated on every page.** To change them, use your editor's find-and-replace across all files (VS Code: Ctrl+Shift+H, or Cmd+Shift+H on Mac) so every page stays in sync.

**Phone numbers:** the number shown on the pages is written in each page's HTML. The numbers used for tracking are listed at the top of `site.js`. If the main number changes, search all files for the old number, in both its dashed form and its digits-only form, and replace it everywhere, including the `DEFAULT_PHONE` line in `site.js`. They must all match.

**Contact form:** the form is on the home page. When someone submits it, `site.js` checks the fields, sends the message to FormSubmit.co in the background, and once FormSubmit confirms it received the message, takes the visitor to `/thank-you/`. If FormSubmit does not confirm, the visitor sees a message with the business phone number and email instead of a "Thanks" page. If a browser cannot send in the background, the form falls back to a normal form post that ends on the same thank-you page. The receiving address is in the form's `action` and in the "Send Email" button (search `formsubmit.co` and `data-mailto` in `index.html`). If you change it, FormSubmit sends a one-time confirmation email to the new address, and the form does not deliver until that link is clicked. The checks and error messages are in `site.js`. After any change to the form, submit a real test and confirm the email arrives.

**Thank-you page:** keep `/thank-you/` and its address as they are. The form and other tools rely on it.

**Analytics and tracking tags:** these are in the `<head>` of every page. If one changes, search all files and replace it everywhere.

**Search engine information:** every page has its own title, description, canonical address and structured data in its `<head>`. Service pages also include their FAQ data there. When you change a FAQ, update both the visible FAQ and the FAQ block in the `<head>`.

**Styling:** `styles.css` was generated by a tool called Tailwind and is compressed onto one line.

- You can swap a class in the HTML for another only if that class already exists in `styles.css`. A class that is not in the file will do nothing.
- For anything new, add normal CSS at the very bottom of `styles.css`, or ask a developer to regenerate it.
- The main colors are at the top of the file (`:root{--primary: ...}`). The hero and service-page headers use fixed color classes, so changing those variables alone will not recolor them.

**Adding a page:** copy an existing folder (for example `services/general-electrical/`), rename it, and edit its text, `<title>`, description, canonical address and structured data. Then add it to `sitemap.xml` and link to it from the menu and footer on every page.

**Adding an image:** put it in `images/` and use a path like `/images/work/my-photo.jpg`. Compress photos first. Under 300 KB is a good target.
